# AI Layer — оркестратор

**Проект**: cursor-starter — шаблон AI-слоя для Cursor.  
**AI Layer Version**: см. [`CHANGELOG.md`](CHANGELOG.md) (semver: правила/команды/оркестратор/bootstrap).  
**Последнее обновление AI-слоя**: 2026-05-13 (Полировка до релиз-готовности: устранены противоречия, добавлена самовалидация, `/reflect` опирается на данные).

## Для чего этот файл

Это **единая точка входа** и главная карта для агента и разработчика. Перед **любой** задачей (даже мелкой) прочитай его (или нужный раздел). Он заменяет длинные повторяющиеся инструкции в чате, экономит токены, делает поведение AI предсказуемым.

**Принципы AI-слоя** — `@.cursor/PRINCIPLES.md` (единый source of truth, не дублируй здесь).  
**Антипаттерны** — `@.cursor/rules/anti-patterns.mdc`.

## Как начинать любую задачу в Cursor (обязательный порядок)

1. **Прочитай этот файл** (или нужный раздел).
2. **Изучи Живую Документацию**: `@PROJECT_KNOWLEDGE.md`.
3. **Составь/обнови `PLAN.md`** (или файл в `.cursor/plans/`) — план обязателен для любой нетривиальной задачи (см. `@.cursor/PRINCIPLES.md` P2).
4. **Подключай контекст точечно**: `@путь/к/файлу` или `@папка/`. Никогда не тащи весь репозиторий. Используй `.cursorignore` для тяжёлых/секретных путей (см. `@.cursor/rules/secrets-guard.mdc`).
5. **Для типовых задач** — используй таблицу маршрутизации ниже или slash-команды из `.cursor/commands/`.
6. **Цикл принятия решения агентом**:
   - Классифицируй задачу по таблице маршрутизации.
   - Прочитай живую документацию и релевантные правила.
   - Составь короткий План на быстрой модели.
   - Открой только нужные `@` файлы + правила.
   - Выполни работу по шагам.
   - **Структурно обнови `PROJECT_KNOWLEDGE.md`** (не append-only лог).
   - Проверь критерии «готово» из команды/плана.
   - Заверши.

## Маршрутизация задач

| Задача | Действие |
|--------|----------|
| Новая фича / крупный рефакторинг | `/feature` или `/refactor` — план в `PLAN.md` → код → тесты → структурно обновить `@PROJECT_KNOWLEDGE.md`. |
| Багфикс / отладка | `/fix-bug` — воспроизвести → починить → регрессионный тест → обновить `@PROJECT_KNOWLEDGE.md`. |
| Ревью кода / PR / диф | `/review` — структурированный разбор по чеклисту. |
| Bootstrap / обновление AI-слоя | `/bootstrap` (обёртка) или вручную `@ai-layer-builder/ai-builder.md` (шаги 0–8). |
| Аудит консистентности AI-слоя | `/audit` — валидатор + ручная проверка дрейфа. |
| Передача контекста в новый чат | `/handoff` — короткий пакет: PLAN, последние изменения, открытые вопросы. |
| Синхронизация документации | `/docs` — обновить `@PROJECT_KNOWLEDGE.md` под фактическое состояние. |
| Рефлексия и самоулучшение | `/reflect` — анализ git + валидатор + журнал. |
| Мелкая правка / быстрый фикс | Ask / Inline / Cmd+K + точечные `@`. Если >5–10 мин или >1 файл — Agent с планом. |
| Использование скила | `/имя-скила` из `@.cursor/rules/project-skills-registry.mdc` (если зарегистрирован). Не выдумывай скилы. |
| Не попадает в таблицу | Ad-hoc план + эскалация к человеку при неоднозначности. |

## Маршрутизация моделей

Пул и эскалация — `@.cursor/rules/model-routing.mdc`. Кратко: по умолчанию ярусы **S/A** (nano, flash, Composer); ярусы **B/C** (Codex, Kimi, Sonnet, Gemini Pro, Grok) — когда задача оправдывает; сначала короткий план на дешёвой модели, затем **явное переключение пользователем в UI**. Модели вне утверждённого пула — только вручную.

## Ссылки на AI-слой

**Правила** (`.mdc` в `.cursor/rules/`):
- `token-economy` — точечный `@`, preCompact, короткие сессии.
- `model-routing` — ярусы S/A/B/C, эскалация.
- `core` — порядок работы агента.
- `architecture` — границы репозитория (после bootstrap — границы проекта).
- `stack-specific` — стек (заглушка до появления кода).
- `project-skills-registry` — проектные skills и правило «не выдумывать».
- `anti-patterns` — что не делать (читается агентом перед задачами на `.md`).
- `secrets-guard` — никаких секретов в живой документации, плане, чате.

**Команды** (`.cursor/commands/*.md`) — см. таблицу маршрутизации.

**Bootstrap**: `@ai-layer-builder/ai-builder.md` — 8 шагов; запускай при смене стека или крупном рефакторинге.

## Обновление AI-слоя

Обновляй при: смене стека / крупном рефакторинге / разъезде конфигурации / добавлении правил-команд / накоплении хаоса в `.cursor/` / после каждого bootstrap нового проекта.

Процесс: `@ai-layer-builder/ai-builder.md` (шаги 0–8) → `node scripts/validate-layer.mjs` → обновить дату в шапке этого файла и `CHANGELOG.md`.
