# Живая документация — cursor-starter

**Назначение**: единственный структурированный снимок «как устроен проект сейчас». Обновляй разделы после задач; не веди append-only журнал (см. `@.cursor/rules/anti-patterns.mdc`).

**Последнее обновление содержания**: 2026-05-13 (полировка до релиз-готовности: устранены противоречия, добавлена самовалидация, `/reflect` опирается на данные).

## Назначение репозитория

Шаблон **AI-слоя** для Cursor: оркестратор `CURSOR.md`, правила `.cursor/rules/`, команды `.cursor/commands/`, сценарий bootstrap в `ai-layer-builder/`, валидатор `scripts/validate-layer.mjs`. Принципы — `@.cursor/PRINCIPLES.md`. История изменений — `@CHANGELOG.md`.

## Текущий стек

Прикладного кода нет. Документация — Markdown / MDC. Скрипты — Node.js (`.mjs`) без сторонних зависимостей. CI — GitHub Actions. После появления прикладного кода обновить `@.cursor/rules/stack-specific.mdc` и этот раздел.

## Точки входа

| Кто | Куда смотреть |
|-----|---------------|
| Человек (первый раз) | `@README.md` → раздел «60-second Quick Start». |
| Агент (любая задача) | `@CURSOR.md` → таблица маршрутизации. |
| Bootstrap / обновление слоя | `/bootstrap` или `@ai-layer-builder/ai-builder.md` (шаги 0–8). |
| Регулярная гигиена | `/audit` (раз в неделю), `/reflect` (раз в 5–10 задач), `/docs` (после рефакторингов). |
| Передача в новый чат | `/handoff`. |

## Правила и инварианты

- **План перед кодом**: `@PLAN.md` (или `.cursor/plans/`) обязателен для любой нетривиальной задачи (P2).
- **Структурная живая документация**: запрещён append-only лог в этом файле (P3, `@.cursor/rules/anti-patterns.mdc`).
- **Маршрутизация моделей**: `@.cursor/rules/model-routing.mdc` (P5).
- **Реестр скилов**: `@.cursor/rules/project-skills-registry.mdc`; агент не выдумывает несуществующие инструменты (P6).
- **Секреты**: никаких токенов/ключей/PII в этом файле, `@PLAN.md`, коммитах (`@.cursor/rules/secrets-guard.mdc`, P9).
- **Версионирование**: каждое изменение AI-слоя фиксируется в `@CHANGELOG.md` (P8).
- **Валидатор**: `node scripts/validate-layer.mjs` зелёный — обязательное условие любого PR.

## AI Layer Health

Раздел отражает реальное состояние слоя по данным валидатора и журнала рефлексий. **Все плейсхолдеры запрещены** — пишутся только подтверждённые значения. Если данных нет — раздел просто кратко указывает источник, откуда они появятся.

### Источники метрик

- **Структурные ошибки и предупреждения** — `node scripts/validate-layer.mjs` (битые ссылки, лимиты, append-only-лог, секреты, синхронность дат).
- **Размеры дифов и частота обновления живой документации** — `git log --shortstat -N`, `git diff --stat`.
- **Версия AI-слоя** — `@CHANGELOG.md` (последний раздел в `[Unreleased]` или последняя версия).
- **Качественные наблюдения** — записи в журнале рефлексий ниже.

## Известные проблемы и долги

- `stack-specific.mdc` — заглушка до появления реального стека приложения. Заменяется при bootstrap brownfield-проекта.
- `project-skills-registry.mdc` — обе таблицы (проектные и глобальные скилы) пустые: в чистом шаблоне это норма; заполняется по мере появления реальных скилов.
- `.cursor/hooks/` — отсутствует в чистом шаблоне; создаётся в шаге 4 `ai-builder.md` при первом запуске в реальном проекте.
- `.github/workflows/validate.yml` рассчитан на Node 20 на `ubuntu-latest`; самопроверка локально на Windows работает напрямую через `node scripts/validate-layer.mjs`.
