# Живая документация — cursor-starter

**Назначение**: единственный структурированный снимок «как устроен проект сейчас». Обновляй разделы после задач; не веди append-only журнал действий.

**Последнее обновление содержания**: 2026-05-12

## Назначение репозитория

Шаблон **AI-слоя** для Cursor: оркестратор `CURSOR.md`, правила `.cursor/rules/`, команды `.cursor/commands/`, сценарий bootstrap в `ai-layer-builder/`.

## Архитектура (логическая)

| Компонент | Роль |
|-----------|------|
| `CURSOR.md` | Точка входа, маршрутизация задач и ссылок на слой |
| `.cursor/rules/*.mdc` | Политики: токены, core, модели, архитектура, стек, реестр скилов |
| `.cursor/commands/*.md` | Slash-сценарии: feature, fix-bug, review, refactor |
| `ai-layer-builder/` | Спеки и пошаговый `ai-builder.md` для переноса слоя в другой проект |
| `PROJECT_KNOWLEDGE.md` | Этот файл — живая память состояния |
| `PLAN.md` | Краткоживущий план текущей задачи (создаётся агентом/человеком) |

## Текущий стек

Прикладного кода нет. Документация — Markdown. После появления кода заполни: языки, сборка, CI, тесты.

## Правила и инварианты

- План перед нетривиальным кодом (`@PLAN.md` или `.cursor/plans/`).
- Маршрутизация моделей: `@.cursor/rules/model-routing.mdc`.
- Реестр глобальных скилов заполняется при bootstrap (шаг 2.5 `ai-builder.md`).

## Известные проблемы и долги

- `stack-specific.mdc` — заглушка до появления реального стека.
- `project-skills-registry.mdc` — таблица сценариев → скил заполняется после скана машины.

## Точки входа для человека

1. Инструкция по шаблону: **`README.md`**.
2. Работа с агентом: новый чат с **`@CURSOR.md`**.
3. Bootstrap под проект: **`@ai-layer-builder/ai-builder.md`**.
