# Живая документация — cursor-starter

**Назначение**: единственный структурированный снимок «как устроен проект сейчас». Обновляй разделы после задач; не веди append-only журнал действий.

**Последнее обновление содержания**: 2026-05-13 (Финал: AI-слой — живая самообучающаяся система, рефлексия через /reflect, hooks генерируются с нуля)

## Назначение репозитория

Шаблон **AI-слоя** для Cursor: оркестратор `CURSOR.md`, правила `.cursor/rules/`, команды `.cursor/commands/`, сценарий bootstrap в `ai-layer-builder/`.

## Архитектура (логическая)

| Компонент | Роль |
|-----------|------|
| `CURSOR.md` | Точка входа, маршрутизация задач и ссылок на слой |
| `.cursor/rules/*.mdc` | Политики: токены, core, модели, архитектура, стек, реестр скилов |
| `.cursor/commands/*.md` | Slash-сценарии: feature, fix-bug, review, refactor, reflect |
| `.cursor/hooks/` | Автоматические проверки и события (plan-guard, knowledge-sync и др.) |
| `ai-layer-builder/` | Спеки и пошаговый `ai-builder.md` для переноса слоя в другой проект |
| `PROJECT_KNOWLEDGE.md` | Этот файл — живая память состояния |
| `PLAN.md` | Краткоживущий план текущей задачи (создаётся агентом/человеком) |
| `.cursor/plans/` | Архив планов (генерируются под проект) |

**Hooks:** активны (см. `.cursor/hooks.json` и `.cursor/hooks/`). Реализованы: plan-guard, knowledge-sync, rule-validator, plan-reminder.

## Текущий стек

Прикладного кода нет. Документация — Markdown. После появления кода заполни: языки, сборка, CI, тесты.

## Правила и инварианты

- **План перед кодом**: `@PLAN.md` (или `.cursor/plans/`) обязателен для любой нетривиальной задачи. План — это чеклист, а не эссе.
- Маршрутизация моделей: `@.cursor/rules/model-routing.mdc`.
- Реестр глобальных скилов: `@.cursor/rules/project-skills-registry.mdc`.

## AI Layer Health (Рефлексия и самоулучшение)

AI-слой — **живая система**. Он не только работает, но и анализирует свои ошибки, улучшает себя, не деградирует.

### Метрики (обновляются при рефлексии)

- **Последняя рефлексия**: (дата)
- **Ошибки агента за последние N задач**: (число + типы: забыл обновить док, огромный диф, выдумал скил)
- **Токены сэкономлены**: (оценка, благодаря hooks + правилам)
- **Хуки**: (список + статус: сработали / не сработали / нуждаются в доработке)

### Механизм рефлексии

1. Пользователь вызывает `/reflect` (см. `.cursor/commands/reflect.md`)
2. AI анализирует последние N чатов/коммитов/задач
3. Находит паттерны: "агент 3 раза забыл обновить `PROJECT_KNOWLEDGE.md`", "plan-guard сработал в 80% коммитов"
4. Предлагает улучшения: новый хук, изменение правила, обновление living docs
5. Обновляет этот раздел

### Цикл самоулучшения

```
bootstrap (ai-builder.md)
  ↓
работа (хуки, команды, правила)
  ↓
рефлексия (/reflect после 5–10 задач)
  ↓
улучшение (новые хуки, правила, обновление docs)
  ↓
(повтор)
```

**Принцип:** AI-слой не статичен. Он рефлексирует, адаптируется, совершенствуется.
