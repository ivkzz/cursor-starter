# Принципы AI-слоя — единственный источник истины

> Этот файл — **single source of truth** для принципов работы AI-слоя в cursor-starter. Все остальные документы (`README.md`, `CURSOR.md`, `PROJECT_KNOWLEDGE.md`, `ai-layer-builder/*.md`, `.cursor/rules/*.mdc`, `.cursor/commands/*.md`) ссылаются на разделы этого файла, а не дублируют его текст.

## P1. AI-слой — живая система, не статичный шаблон

AI-слой:
1. **Анализирует** проект, в который помещён.
2. **Генерирует** хуки, команды, правила **с нуля** — без готовых примеров, которые могут подойти не любому проекту.
3. **Дисциплинирует** работу агента и команды (token economy, plan-driven, структурная документация).
4. **Рефлексирует** и улучшает себя через `/reflect` (на основе git, валидатора, журнала, а не «истории чатов»).
5. **Версионируется** через `CHANGELOG.md` и поле `AI Layer Version` в `CURSOR.md`.

## P2. Plan-Driven Development

Перед любой нетривиальной задачей (фича, багфикс, рефакторинг, многошаговый рефлекс):
1. Создать/обновить `PLAN.md` (или файл в `.cursor/plans/`).
2. План — **чеклист**, не эссе: цель, контекст, шаги, риски, критерий «готово».
3. План **обязателен**. Без плана — только мелкие правки через Ask/Inline/Cmd+K.

## P3. Структурная живая документация (запрет append-only лога)

`PROJECT_KNOWLEDGE.md` — память состояния, а не дневник:
- **Можно** обновлять разделы: Архитектура, Точки входа, Правила валидации, Известные проблемы, Текущий стек, Журнал рефлексий.
- **Нельзя** вести лог в стиле «я добавил файл X», «починил баг Y», «обновил дату».
- Документация показывает **«как код работает сейчас»**, чтобы новый чат с `@PROJECT_KNOWLEDGE.md` мгновенно вошёл в курс без перечитывания истории.

## P4. Token economy

Главный расход — **не длина одного промпта**, а контекст (файлы + история чата + tool calls).

Правила выживания контекста:
1. По умолчанию — **быстрые модели / Composer** (ярусы S/A — см. `@.cursor/rules/model-routing.mdc`).
2. Точечный `@`: подключай **только нужные файлы**, не папки.
3. `.cursorignore` для тяжёлых/секретных путей (экономия 50–80% контекста на типичных проектах).
4. **Новый чат на новую задачу** + ссылка на `@CURSOR.md`. Длинная история удорожает каждый запрос.
5. **PreCompact / compaction**: при росте контекста — сжимай вывод, обновляй `PROJECT_KNOWLEDGE.md` структурно, начинай новый чат.
6. Перед тяжёлым Agent-прогоном — **Plan Mode** (Shift+Tab). Короткий план дешевле любых переделок.
7. Мелкие правки (< 5–10 минут, 1–2 файла) — Ask/Inline/Cmd+K вместо полного Agent.

## P5. Маршрутизация моделей

Конкретный пул и ярусы — `@.cursor/rules/model-routing.mdc`. Кратко:
- **S** (nano, flash) — классификация задачи, короткий план, форматирование.
- **A** (Composer) — повседневная разработка, типовые правки.
- **B** (Codex, Kimi) — реализация по чёткому ТЗ, большие дифы, длинный контекст.
- **C** (Sonnet, Gemini Pro, Grok) — архитектура, безопасность, сложная отладка.

**Эскалация на C — всегда после короткого плана на S/A и явного переключения пользователем.**

## P6. Bootstrap «с нуля под проект»

`ai-layer-builder/ai-builder.md` — сценарий из 8 шагов:
1. Не «натягивает шаблон», а **проектирует управляемую автономию**.
2. **Анализирует проект** (стек, структура, процессы), а не предполагает.
3. **Генерирует** хуки/правила/команды **с нуля**, опираясь на найденное. Хуки в чистом шаблоне отсутствуют — появляются при bootstrap.
4. **Merge, не выжигай**: существующий `.cursor/`, `CURSOR.md`, `hooks.json` — дополняй; полная перезапись только по явной просьбе.
5. **Не выдумывает несуществующие скилы**: пользуется только тем, что реально найдено или явно зарегистрировано пользователем.

## P7. Минимализм AI-слоя

Каждая сущность (правило, команда, скрипт) должна **окупаться**:
- Решает реальную проблему, замеченную хотя бы 3 раза.
- Не дублирует существующее.
- Имеет один фокус.

«Энциклопедии», «полные шаблоны на все случаи», избыточные правила — антипаттерн (см. `@.cursor/rules/anti-patterns.mdc`).

## P8. Дисциплина против дрейфа

- `CURSOR.md`, `.cursor/rules/*.mdc`, `.cursor/commands/*.md` не должны противоречить друг другу.
- Валидатор `scripts/validate-layer.mjs` гонится локально и на CI (`.github/workflows/validate.yml`).
- При расхождении «документация vs факт» — правит **документацию структурно** (см. P3), а не «приписывает в конец».

## P9. Безопасность по умолчанию

- Секреты, токены, PII — **никогда** в `PROJECT_KNOWLEDGE.md`, `PLAN.md`, чат, коммиты.
- `.cursorignore` исключает `.env`, `*.pem`, `*.key`, `.aws/`, `.ssh/`, `secrets/`.
- Правило `@.cursor/rules/secrets-guard.mdc` — обязательное чтение перед любой работой с конфигами/окружением.

## P10. Рефлексия как контур обратной связи

```
bootstrap (ai-builder.md)
    ↓
работа (правила, команды, точечный @, план перед кодом)
    ↓
рефлексия (/reflect — раз в 5–10 задач, на основе git+валидатора, не воображения)
    ↓
улучшение (новые/изменённые правила, команды, секции PROJECT_KNOWLEDGE.md)
    ↓
обновление CHANGELOG.md и AI Layer Version
    ↓
(повтор)
```

Без этого контура AI-слой деградирует.
