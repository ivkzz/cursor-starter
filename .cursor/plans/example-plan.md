# Пример плана (stack-agnostic): добавить slash-команду в AI-слой

> Это **пример формы плана**, а не пример «как делать вашу фичу». Стек репозитория здесь — сам AI-слой; пример не закрепляет никакой прикладной стек и подходит для любого проекта.

**Цель**: добавить новую проектную slash-команду `/example-cmd` в `.cursor/commands/`, оформив её строго по `@ai-layer-builder/spec-commands.md`, и отразить её в маршрутизации `@CURSOR.md`.

---

## Контекст

**@ файлы и артефакты:**
- `@CURSOR.md` — карта маршрутизации задач.
- `@ai-layer-builder/spec-commands.md` — формат файла команды.
- `@PROJECT_KNOWLEDGE.md` — где описать новую команду структурно (раздел «Архитектура»).
- `.cursor/commands/` — папка с существующими командами для подражания структуре.
- `.cursor/rules/` — правила, на которые команда может опираться.

**Затронутые модули (минимум — только то, что реально меняется):**
- `.cursor/commands/example-cmd.md` (новый файл).
- `CURSOR.md` (одна строка в таблице маршрутизации).
- `PROJECT_KNOWLEDGE.md` (раздел «Архитектура»: пополнить список команд).

---

## Шаги

### 1. Согласование
- [ ] Зафиксировать **одно** действие команды (имя в kebab-case → `/имя`).
- [ ] Описать вход, шаги, ограничения, критерий «готово».
- [ ] Убедиться, что команда не дублирует существующие (`/feature`, `/fix-bug`, `/review`, `/refactor`, `/reflect`).

### 2. Реализация
- [ ] Создать `.cursor/commands/example-cmd.md` по структуре из `spec-commands.md`.
- [ ] Первый шаг внутри команды — **обязательно** обязать агента составить `PLAN.md`.
- [ ] Последний шаг — обязать обновить `PROJECT_KNOWLEDGE.md` структурно (не логом).

### 3. Маршрутизация
- [ ] Добавить строку в таблицу маршрутизации `CURSOR.md` (что → `/example-cmd`).
- [ ] При необходимости — упомянуть в `README.md` в таблице slash-команд.

### 4. Документация
- [ ] Обновить раздел «Архитектура → Команды» в `PROJECT_KNOWLEDGE.md`.
- [ ] Не вести лог («добавил команду X») — описать роль команды в системе.

### 5. Самопроверка
- [ ] Прогнать валидатор шаблона (`node scripts/validate-layer.mjs` — см. `@scripts/validate-layer.mjs`).
- [ ] Битых `@`-ссылок нет, лимиты строк соблюдены.

---

## Риски

| Риск | Вероятность | Влияние | Митигация |
|------|-------------|---------|-----------|
| Дублирование с существующими командами | Средняя | Среднее | Прочитать все `.cursor/commands/*.md` перед созданием. |
| Раздувание AI-слоя без реальной пользы | Средняя | Высокое | Применять принцип минимализма из `@.cursor/PRINCIPLES.md`: команда оправдана только если экономит 3+ шага в типовом сценарии. |
| Расхождение между CURSOR.md и фактом | Низкая | Среднее | Валидатор проверяет ссылки и упоминания. |

---

## Готово, когда

- [ ] Файл команды создан и проходит валидатор.
- [ ] `CURSOR.md` и `PROJECT_KNOWLEDGE.md` обновлены **структурно**.
- [ ] План в `PLAN.md` закрыт (или перенесён в архив).
- [ ] Соблюдена дисциплина: план перед кодом, минимум сущностей, нет append-only лога.

---

**Принцип**: этот шаблон плана — `single source of truth` по форме. Для любой задачи (новая фича, багфикс, рефакторинг) — заполняй те же четыре блока: **Цель → Контекст → Шаги → Риски → Готово**.
