# /refactor — Безопасный рефакторинг с опорой на тесты

Файл в `.cursor/commands/refactor.md` — текст, который подставляется в чат при выборе `/refactor`.

## Цель
Изменить структуру кода без смены поведения (или с явно согласованным изменением контракта), с тестами и обновлённой живой документацией.

## Входы
- Цель рефакторинга (что улучшаем: связность, имена, выделение модуля и т.д.).
- Область: файлы/пакеты (или «найди сам» с последующим согласованием границ).

## Шаги для агента (обязательный порядок)

1. **Составить План** в `@PLAN.md` или `.cursor/plans/refactor-xxx.md`: текущее состояние, целевое, шаги, риски регрессий, какие тесты запускать на каждом шаге.
2. **Зафиксировать поведение**: существующие тесты или минимальные новые, которые ловят контракт до изменений.
3. **Малыми шагами**: предпочитай несколько маленьких коммитов/итераций одному гигантскому дифу.
4. **Рефакторинг**: следуй `@.cursor/rules/architecture.mdc` и `stack-specific.mdc` (когда заполнены).
5. **Прогон тестов** после каждого логического шага; зелёная ветка — критерий продолжения.
6. **Обновить Живую Документацию** структурно: архитектура, точки входа, затронутые правила валидации.
7. При неоднозначности целевой архитектуры — по `model-routing.mdc` предложи эскалацию на ярус C **до** больших перестроек.

## Ограничения
- Не меняй публичные API без явного согласования в плане.
- Не смешивай рефакторинг с новой фичей в одном дифе.

## Готово
- Тесты зелёные, поведение не сломано (или контракт явно обновлён и задокументирован).
- `@PROJECT_KNOWLEDGE.md` отражает новую структуру.
- План закрыт.
