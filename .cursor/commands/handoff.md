# /handoff — Пакет контекста для следующего чата

Файл в `.cursor/commands/handoff.md` — текст, который подставляется в чат при выборе `/handoff`.

## Цель

Сжать состояние текущей сессии до короткого markdown-блока (≤ 25 строк), который можно скопировать в новый чат вместе с `@CURSOR.md`. Решает базовую боль: длинная история чата дорожает с каждым запросом (`@.cursor/PRINCIPLES.md` P4), поэтому правильная стратегия — новый чат + пакет передачи.

## Входы

- (Опционально) Область: «вся сессия», «только текущая задача из `PLAN.md`».

## Шаги для агента (обязательный порядок)

1. **Прочитать**: `@PLAN.md`, последние записи в `@PROJECT_KNOWLEDGE.md`, `git log --oneline -10`, `git status --short`.
2. **Составить пакет** строго по структуре ниже. Не превышай 25 строк суммарно.

```markdown
# Handoff — <короткое название задачи>

**Текущий план**: см. `@PLAN.md` (одной строкой — что в нём активно).
**Что уже сделано**: 3–5 пунктов, по существу.
**Что осталось**: 3–5 пунктов с явными следующими шагами.
**Открытые вопросы**: 1–3 пункта (если есть).
**Контекст для @-ссылок**: `@CURSOR.md`, `@PROJECT_KNOWLEDGE.md`, и 2–4 ключевых файла.
**Известные риски/блоки**: 1–2 строки (если есть).
```

3. **Вывести пакет** пользователю одним блоком — без воды, без логов «я сделал», без перечисления всех файлов.
4. Если пакет получается длиннее 25 строк — сжать ещё раз (это не план, это сводка).

## Ограничения

- **Не** копировать содержимое `PROJECT_KNOWLEDGE.md` — только ссылку.
- **Не** перечислять все коммиты — только 1–2 ключевых.
- **Не** пересказывать историю чата.
- **Не** обновлять `PROJECT_KNOWLEDGE.md` (это просто пакет, а не задача).

## Готово

- Пакет передан в чат одним блоком.
- Пользователь может скопировать его в новый чат с `@CURSOR.md` и сразу продолжить.
