# /reflect — Рефлексия AI-слоя на основе данных, не воображения

Файл в `.cursor/commands/reflect.md` — текст, который подставляется в чат при выборе `/reflect`.

## Цель

Найти паттерны ошибок и неэффективности AI-слоя за последние N коммитов / дней, сформулировать **конкретные** предложения по эволюции (новые/изменённые правила, команды, антипаттерны), записать короткую запись в журнал рефлексий внутри `@PROJECT_KNOWLEDGE.md` (раздел «AI Layer Health → Журнал рефлексий»). Источники — **только реальные**: git, валидатор, файлы. См. `@.cursor/PRINCIPLES.md` P10.

## Входы

- N (по умолчанию 10) — количество коммитов для анализа.
- Период (опционально) — «последние 7 дней», «с тега vX.Y.Z».

## Шаги для агента (обязательный порядок)

1. **Составить План** в `@PLAN.md` или `.cursor/plans/reflect-xxx.md`: что анализируем, какие источники, какие метрики.

2. **Собрать данные из реальных источников** (никаких «припомню историю чатов»):
   - `git log --pretty=format:"%h %ad %s" --date=short -N` — последние коммиты.
   - `git log -N --shortstat` — размеры дифов (выявить «огромные» — > 800 строк суммарно).
   - `git diff --stat <от>..<до>` — какие модули чаще меняются.
   - Запустить `node scripts/validate-layer.mjs` — текущее состояние «здоровья».
   - Прочитать `@PROJECT_KNOWLEDGE.md` (особенно раздел «AI Layer Health/Журнал рефлексий»): что фиксировалось ранее, что устарело.
   - Прочитать активный `@PLAN.md`: ведётся ли план реально или висит «завершённый».
   - Просмотреть `@CHANGELOG.md` — какие принципиальные изменения были с прошлого `/reflect`.

3. **Анализ паттернов** (на основе собранных данных):
   - **Огромные дифы**: коммиты > 800 строк → антипаттерн P? («Огромный диф без разбиения»).
   - **Долгий завершённый план в `PLAN.md`** → нарушение «после завершения — очистить/перенести».
   - **Дрейф документации**: код менялся, а `PROJECT_KNOWLEDGE.md` не обновлялся в тех же датах.
   - **Битые ссылки или предупреждения валидатора**, которые повторяются от прогона к прогону.
   - **Скилы вне реестра**, упомянутые в коммитах/планах → нарушение «не выдумывать скилы».
   - **Использование сильных моделей без плана** (если такая информация есть в коммитах/обсуждениях).

4. **Предложения** — конкретные, минимальные (P7):
   - «Уточнить лимит дифа в `feature.md` с 800 до 600 — последние 3 PR пробивают потолок».
   - «Добавить запись в `anti-patterns.mdc`: <конкретная формулировка>».
   - «Удалить раздел X из `PROJECT_KNOWLEDGE.md` — устарел, нет ссылок».
   - «Создать новую команду `/<name>` — повторяется ≥ 3 раз в последних задачах».
   - Каждое предложение — **обоснование одной строкой** и пометка `must / should / consider`.

5. **Записать короткую запись в журнал**:
   - Открой `@PROJECT_KNOWLEDGE.md` → раздел «AI Layer Health → Журнал рефлексий».
   - **Добавь** новую запись (3–7 строк, формат ниже). Не правь предыдущие записи и не превращай журнал в эссе.

```
### YYYY-MM-DD — рефлексия #<N>

- **Окно**: <период / N коммитов>.
- **Найдено**: <1–3 ключевых наблюдения>.
- **Предложено**: <1–3 must/should/consider>.
- **Применено сразу**: <если что-то починили в рамках этой же сессии>.
```

6. **При применении изменений в этой же сессии**:
   - Обновить `CHANGELOG.md` (раздел `[Unreleased]`).
   - Применять только **точечные** правки (правила/команды/документация). Большие изменения — отдельной задачей `/refactor` или `/feature`.

## Ограничения

- **Не использовать «припомню/восстановлю историю чатов»** — это источник из воображения, не данные.
- **Не предлагать изменения, противоречащие `@.cursor/PRINCIPLES.md`** (P1–P10).
- **Не раздувать AI-слой**: новое правило/команда оправданы только если решают наблюдаемую проблему (P7).
- Лимит изменений в этой же сессии — 1–3 файла; всё больше — отдельной задачей.

## Готово

- В `@PROJECT_KNOWLEDGE.md` появилась новая запись в журнале рефлексий.
- Если применены правки — `CHANGELOG.md` обновлён, валидатор зелёный.
- План `reflect-xxx.md` закрыт.
- Предложения, не применённые сразу, сформулированы как кандидаты на следующий PR/задачу.

---

**Принцип**: AI-слой не статичен — он рефлексирует **по данным**, а не по ощущениям. `/reflect` — это механизм самоулучшения с обратной связью.
